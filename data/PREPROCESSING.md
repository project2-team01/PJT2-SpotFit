## 1. 읽기 공통 규칙

- 모든 CSV는 `pd.read_csv(path, encoding="utf-8-sig")`로 읽습니다.
- 코드 컬럼(행정동·자치구·상권)은 **정수(int)** 로 맞춥니다.
- 이름에 들어간 `?`는 원래 가운뎃점(`·`)입니다. 행정동 7개(`종로1?2?3?4가동`, `상계3?4동` 등)와 상권 1개(`종로?청계 관광특구`)가 그렇습니다.
  - 표시용 이름은 `.str.replace("?", "·", regex=False)`로 고칩니다.
  - **조인은 코드로 합니다.** 이름으로 조인하는 건 SKT 데이터 하나뿐입니다 (2.3절).

### 2.3 SKT 데이터는 이름으로 조인

- SKT 7자리 코드를 geojson(`adm_cd[:7]`)을 거쳐 상권분석 8자리로 바꾸면 **8개 동이 빠집니다.** 상일동, 강일동, 일원2동, 용신동, 가양1동, 방화3동, 오류2동, 항동입니다.
- **자치구 + 행정동 이름**으로 조인하면 SKT의 424개 동이 모두 붙습니다. 빠지는 건 원래 SKT에 없는 **항동** 하나뿐입니다.
- SKT 이름은 처음부터 `·`를 씁니다. 상권분석 이름의 `?`만 바꾸면 됩니다.
- ⚠️ 동 이름 컬럼명이 파일마다 다릅니다. 통신정보는 `행정동`, 관심집단은 `행정동명`입니다.

```python
master["행정동_명"] = master["행정동_명"].str.replace("?", "·", regex=False)
skt_key = (skt[["자치구", "행정동", "행정동코드"]].drop_duplicates()   # 관심집단은 "행정동명"
             .rename(columns={"자치구": "자치구_명", "행정동": "행정동_명", "행정동코드": "SKT_코드"}))
master = master.merge(skt_key, on=["자치구_명", "행정동_명"], how="left")   # 항동만 NaN
```

### 2.4 2025년에 쪼개진 동: 새 동을 옛 동으로 합치기

상권분석과 SKT는 쪼개지기 전의 동을 씁니다. 소상공인과 경계 geojson은 2025-12 기준의 새 동을 씁니다.

| 상권분석 동 (기준) | 2025-12 새 코드 |
|:---|:---|
| 용신동 `11230536` | 신설동 `11230515` + 용두동 `11230533` |
| 상일동 `11740520` | 상일1동(상일제1동) `11740525` + 상일2동(상일제2동) `11740526` |
| 일원2동 `11680740` | 개포3동 `11680675` (이름만 바뀜) |

```python
NEW_TO_OLD = {11230515: 11230536, 11230533: 11230536,
              11740525: 11740520, 11740526: 11740520,
              11680675: 11680740}
sbiz["행정동_코드"] = sbiz["행정동코드"].replace(NEW_TO_OLD)
```

- 점포 수처럼 **더할 수 있는 값은 더합니다.** 비율은 더한 값으로 다시 계산합니다.
- 반대 방향(옛 동을 새 동으로 나누기)은 나누는 기준이 없으니 하지 않습니다.

## 3. 기간 맞추기

| 데이터 | 원본 기간 | 분기로 맞추는 법 |
|:---|:---|:---|
| 상권분석 소비, 길단위(유동)인구 (행정동·상권), 추정매출, 점포, 상권변화지표 | 분기 | 그대로 씁니다. |
| 상주인구·직장인구·아파트·집객시설 (행정동), 상주인구·직장인구·집객시설 (상권) | 분기 | **4개 분기 값이 모두 같습니다** (확인함). 분기 표에 넣지 말고 마스터에 **값 1개**만 둡니다. |
| SKT 통신정보·관심집단 | 2025년 3·6·9·12월 | 3월 → `20251`, 6월 → `20252`, 9월 → `20253`, 12월 → `20254`. **분기 평균이 아니라 분기말 한 달의 값**입니다. |
| 네이버 검색 트렌드 | 월 12개 | 3개월 평균으로 분기 값을 만듭니다. |
| 소상공인 상가정보 | 2025-12-31 한 장 | `20254` 시점 값입니다. 마스터에는 `점포_202512_전체`처럼 시점을 이름에 넣습니다. |
| 국민연금 평균소득월액 | 2025-12 | 자치구의 고정 값입니다. |
| 영역, 경계, 재현데이터 | 기간 없음 | 고정 값입니다. |

```python
MONTH_TO_Q = {"03": 20251, "06": 20252, "09": 20253, "12": 20254}
skt["기준_년분기_코드"] = MONTH_TO_Q[month]                # 파일명 통신정보_2025.MM.xlsx 의 MM
naver["기준_년분기_코드"] = 20250 + (pd.to_datetime(naver["period"]).dt.month - 1) // 3 + 1
```

> 4개 분기 값이 같은 변수를 1,700행 분기 표에 넣으면, 표본이 1,700개인 것처럼 보이지만 실제로는 425개입니다.

### 4.3 일부러 넣지 않은 것

- **네이버 검색지수**: 10개 카테고리 파일은 서울 전체 값입니다. 25개 구 파일은 구마다 따로 잰 상대값이라 구끼리 비교할 수 없습니다. 쓸 때 3장 코드로 분기를 맞춥니다.
- **재현데이터**: 합성 데이터라 넣지 않았습니다.
- **추정매출의 요일·시간대·성별·연령 세부 컬럼**: 필요하면 원본에서 붙이고, 5장 규칙을 적용합니다.
- **점포의 `개업_율`·`폐업_률`**: 잘못 평균 내기 쉬워서 빼고, 개수만 넣었습니다 (5장).

## 5. 값 정리 규칙

| 대상 | 문제 | 처리 |
|:---|:---|:---|
| 집객시설 (행정동·상권) | 빈칸은 있는데 0이 하나도 없습니다. 빈칸이 곧 '0개'입니다. | `fillna(0)`. `집객시설_수`는 하위 항목의 합보다 항상 큽니다(다른 시설도 포함). 다시 계산하지 말고 원래 값을 씁니다. |
| 아파트 면적·가격 구간별 세대 수 | 빈칸 | 해당 세대가 없다는 뜻으로 보고 `fillna(0)` (추정) |
| 추정매출 시간대별 **건수** 컬럼 | `시간대_건수~06_매출_건수`처럼 이름이 깨져 있습니다. | `~06`, `~11`, `~14`, `~17`, `~21`, `~24`를 `00~06`, `06~11`, `11~14`, `14~17`, `17~21`, `21~24`로 바꿉니다. |
| 추정매출 성별·연령 | `남성 + 여성` 합계는 `당월_매출_금액`의 88.6%뿐입니다. | 성별·연령 비중의 분모는 `남성 + 여성` 합계로 잡습니다. |
